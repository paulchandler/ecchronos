# rest module — guidance for Claude Code

## Interface/Implementation convention

Every controller must be defined as an interface first, with a corresponding `*Impl` class carrying all Spring MVC annotations (`@RestController`, `@GetMapping`, etc.). The interface stays annotation-free and documents only the method signatures. Follow the existing pattern: `ScheduleRepairManagementREST` / `ScheduleRepairManagementRESTImpl`.

## Endpoint paths — use the shared prefix constant

All `/repair-management/v2/` endpoints must use the constant from `RestUtils`:

```java
import static com.ericsson.bss.cassandra.ecchronos.rest.RestUtils.REPAIR_MANAGEMENT_ENDPOINT_PREFIX;

@GetMapping(REPAIR_MANAGEMENT_ENDPOINT_PREFIX + "/your-path")
```

Do not hardcode the path string. If the version or root ever changes, `RestUtils` is the single place to update.

## Parameter validation — use `RestUtils` helpers and `ResponseStatusException`

- Parse UUID path/query parameters with `RestUtils.parseIdOrThrow()` — it throws `400 BAD_REQUEST` on malformed input automatically.
- Throw `ResponseStatusException` directly for all other validation failures. Do not create custom exception classes in this module.

```java
if (table != null && keyspace == null)
{
    throw new ResponseStatusException(BAD_REQUEST, "keyspace must be provided if table is provided");
}
```

The two status codes used across the module are `BAD_REQUEST (400)` and `NOT_FOUND (404)`.

## Response models live in `core`, not here

Data transfer types (`Schedule`, `OnDemandRepair`, `RepairInfo`, `RepairStats`, `VirtualNodeState`, `ScheduleConfig`) are defined in `core/repair/types/`. Do not add new response model classes to the `rest` module. Add them to `core` instead.

## No security configuration here

Authentication and TLS are configured entirely in the `application` module. Do not add Spring Security annotations (`@Secured`, `@PreAuthorize`) or security configuration classes to this module.

## No application configuration here

This module does not contain `application.yml`, `application.properties`, or Spring Boot auto-configuration. All that lives in the `application` module.

## `PrometheusMeterRegistry` is optional

`MetricsREST` injects the registry with `@Autowired(required = false)`. This is intentional — deployments without Prometheus configured must still start successfully. Do not change this to a required dependency.

## Testing — no embedded server, no Spring context

Tests instantiate controllers directly with Mockito mocks. Do not introduce `@SpringBootTest`, `MockMvc`, or Testcontainers into this module's tests — they are not needed and would slow the build significantly.

```java
@RunWith(MockitoJUnitRunner.Silent.class)
public class TestMyControllerImpl
{
    @Mock
    private SomeCoreDependency myDependency;

    private MyControllerImpl myController;

    @Before
    public void setUp()
    {
        myController = new MyControllerImpl(myDependency);
    }
}
```

Tests use **JUnit 4** (junit-vintage-engine). Keep new tests consistent with this — do not mix in JUnit 5 annotations.

## Adding a new endpoint — checklist

1. Define the method signature in the relevant `*REST` interface (or create a new interface if the concern is separate)
2. Implement in the `*RESTImpl` class with Spring MVC mapping annotations and OpenAPI `@Operation`/`@Parameter` annotations
3. Use `REPAIR_MANAGEMENT_ENDPOINT_PREFIX` for repair management paths; create an equivalent constant in `RestUtils` for any new path prefix
4. Add unit tests covering: happy path, all invalid parameter combinations (`400`), not-found cases (`404`)
5. Add response model to `core/repair/types/` if needed
6. Regenerate the OpenAPI spec:
   ```bash
   mvn verify -P python-integration-tests
   ```
   The updated `docs/autogenerated/openapi.yaml` must be committed alongside the code change.

## OSGi note

The comment at the top of each `*RESTImpl` file — *"When updating the path it should also be updated in the OSGi component"* — means any path change must also be applied in the OSGi integration module. Check `osgi-integration/` for the corresponding component registration.
