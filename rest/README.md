# rest

The `rest` module exposes the ecChronos HTTP API. It provides Spring MVC `@RestController` beans for repair scheduling, on-demand repairs, repair information, Prometheus metrics, and time-based run policy (blackout window) management.

This module contains controllers and their interfaces only. Configuration, security, and Spring Boot wiring live in the `application` module.

## Package Structure

```
com.ericsson.bss.cassandra.ecchronos.rest
├── RepairManagementREST.java              # Interface: repair info endpoint
├── RepairManagementRESTImpl.java          # GET /repair-management/v2/repairInfo
├── ScheduleRepairManagementREST.java      # Interface: schedule endpoints
├── ScheduleRepairManagementRESTImpl.java  # GET /repair-management/v2/schedules
├── OnDemandRepairManagementREST.java      # Interface: on-demand repair endpoints
├── OnDemandRepairManagementRESTImpl.java  # GET/POST /repair-management/v2/repairs
├── MetricsREST.java                       # GET /metrics
├── RejectConfigREST.java                  # GET/POST/PATCH/DELETE /rejections
└── RestUtils.java                         # UUID parsing and duration helpers
```

Response/request data models (`Schedule`, `OnDemandRepair`, `RepairInfo`, etc.) are defined in the `core` module under `core/repair/types/`.

## API Reference

All paths are relative to the server root (default `https://localhost:8080`). The full OpenAPI specification is generated at `docs/autogenerated/openapi.yaml`.

### Repair Information

#### `GET /repair-management/v2/repairInfo`

Returns repair statistics for one or more tables over a time window.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `keyspace` | string | conditional | Keyspace name. Required if `table` is provided. |
| `table` | string | no | Table name. Requires `keyspace`. |
| `since` | long | conditional | Start of time window (epoch ms or ISO 8601). Required together with `duration` if no `keyspace`+`table` scope given. |
| `duration` | string | conditional | Length of time window (e.g. `30s`, `PT30S`). Required together with `since` if no scope given. |
| `isLocal` | boolean | no | `true` = local node only; `false` (default) = cluster-wide. |

**Response:** `RepairInfo`

If neither `since` nor `duration` are provided the window defaults to `now - GC_GRACE_SECONDS` → `now` for the target table.

**Errors:**
- `400` — `table` supplied without `keyspace`; only one of `since`/`duration` provided; `since + duration` resolves to a future end time
- `404` — table does not exist

### Schedules

#### `GET /repair-management/v2/schedules`

Returns all scheduled repair jobs, optionally filtered by keyspace or table.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `keyspace` | string | no | Filter to a specific keyspace. |
| `table` | string | no | Filter to a specific table. Requires `keyspace`. |

**Response:** `List<Schedule>`

**Errors:** `400` — `table` supplied without `keyspace`

---

#### `GET /repair-management/v2/schedules/{id}`

Returns a single scheduled repair job by its UUID.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `id` | UUID (path) | yes | Job identifier. |
| `full` | boolean | no | If `true`, includes per-vnode repair state in the response. |

**Response:** `Schedule`

**Errors:** `400` — malformed UUID; `404` — job not found

---

#### `GET /repair-management/v2/running-job`

Returns a human-readable string describing the job currently executing on this node, or an indication that no job is running.

**Response:** `String`

---

### On-Demand Repairs

#### `GET /repair-management/v2/repairs`

Lists on-demand repair jobs, optionally filtered.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `keyspace` | string | no | Filter by keyspace. |
| `table` | string | no | Filter by table. Requires `keyspace`. |
| `hostId` | UUID | no | Filter to a specific node. |

**Response:** `List<OnDemandRepair>`

**Errors:** `400` — `table` supplied without `keyspace`

---

#### `GET /repair-management/v2/repairs/{id}`

Returns on-demand repair job(s) matching a given ID. Multiple results are possible when a cluster-wide repair spawns one job per node.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `id` | UUID (path) | yes | Repair job identifier. |
| `hostId` | UUID | no | Optionally filter to a specific node. |

**Response:** `List<OnDemandRepair>`

**Errors:** `400` — malformed UUID; `404` — repair not found

---

#### `POST /repair-management/v2/repairs`

Schedules an on-demand repair immediately.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `keyspace` | string | conditional | Keyspace to repair. Required if `table` provided. Omit for all tables. |
| `table` | string | no | Table to repair. Requires `keyspace`. Omit for all tables in keyspace. |
| `repairType` | enum | no | `VNODE` (default), `PARALLEL_VNODE`, or `INCREMENTAL`. |
| `isLocal` | boolean | no | `true` = repair only local node; `false` (default) = cluster-wide. |

**Response:** `List<OnDemandRepair>` — one entry per node targeted (cluster-wide), or one entry (local).

**Errors:** `400` — `table` without `keyspace`; `404` — table does not exist or is not replicated

---

### Rejection (Blackout Window) Configuration

These endpoints manage time-based blackout windows stored in `ecchronos.reject_configuration`.

#### `GET /rejections`

Returns currently configured blackout windows.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `keyspace` | string | no | Filter by keyspace. |
| `table` | string | no | Filter by table. Requires `keyspace`. |

**Response:** `List<TimeBasedRunPolicyBucket>`

---

#### `POST /rejections`

Creates a new blackout window via Compare-And-Set insert.

**Request body:** `TimeBasedRunPolicyBucket` (JSON)

**Response:** `{ "data": [...], "message": "..." }` — includes all current rejections and a success/failure message reflecting the CAS result.

---

#### `PATCH /rejections`

Adds datacenter exclusions to an existing blackout window.

**Request body:** `TimeBasedRunPolicyBucket` (JSON)

**Response:** `{ "data": [...], "message": "..." }`

---

#### `DELETE /rejections`

Removes a blackout window. If the request body includes datacenter exclusions, only those datacenters are removed from the exclusion set; if the exclusion set is empty after removal the entire row is deleted.

**Request body:** `TimeBasedRunPolicyBucket` (JSON)

**Response:** `{ "data": [...], "message": "..." }`

---

#### `DELETE /rejections/all`

Truncates the entire `ecchronos.reject_configuration` table.

**Response:** `{ "data": [], "message": "..." }`

---

### Metrics

#### `GET /metrics`

Exposes collected metrics in Prometheus or OpenMetrics format. Requires a `PrometheusMeterRegistry` bean to be present; returns `404` if metrics are not configured.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `name[]` | string (multi) | no | Filter output to named metrics only. |
| `Accept` | header | no | `application/openmetrics-text` for OpenMetrics v1.0.0; defaults to Prometheus text v0.0.4. |

**Response:** Plain text metrics in the requested format.

## Error Handling

Controllers use Spring's `ResponseStatusException` to map errors to HTTP status codes. No custom exception class exists at the REST layer — exceptions from the core layer bubble up and are caught in the controller.

| Status | Cause |
|---|---|
| `400 BAD_REQUEST` | Invalid parameter combinations; malformed UUID; `table` without `keyspace` |
| `404 NOT_FOUND` | Table or job not found; metrics not configured; CQL failures in rejection endpoints |

## Testing

All tests use **JUnit 4 + Mockito** with `@RunWith(MockitoJUnitRunner.Silent.class)`. There is no embedded server or Testcontainers usage in this module — controllers are instantiated directly with mocked dependencies.

### Test classes

| Test class | Controller under test |
|---|---|
| `TestRepairManagementRESTImpl` | `RepairManagementRESTImpl` |
| `TestScheduleRepairManagementRESTImpl` | `ScheduleRepairManagementRESTImpl` |
| `TestOnDemandRepairManagementRESTImpl` | `OnDemandRepairManagementRESTImpl` |
| `TestMetricsREST` | `MetricsREST` |
| `TestRejectConfigREST` | `RejectConfigREST` |
| `RestUtilsTest` | `RestUtils` |

### Key test patterns

- **Parameter validation** — every invalid query parameter combination has a dedicated test that asserts the correct `ResponseStatusException` status code is thrown
- **Filter predicate coverage** — `getRepairs` and `getSchedules` tests cover all query parameter combinations (none, keyspace only, keyspace+table, hostId)
- **Default value tests** — verify that omitting `since`/`duration` falls back to GC_GRACE_SECONDS, and that omitting `repairType` defaults to `VNODE`
- **CAS result handling** — `RejectConfigREST` tests mock `ResultSet` with `wasApplied()` returning both `true` and `false` to cover success and failure response messages

## OpenAPI Specification

The OpenAPI 3.0.1 specification is auto-generated and committed at `docs/autogenerated/openapi.yaml`. It must be regenerated after any endpoint change:

```bash
mvn verify -P python-integration-tests
```

Endpoints are grouped under two OpenAPI tags:
- `Repair-Management` — all `/repair-management/v2/` paths
- `Reject-Configuration` — all `/rejections` paths
- `Metrics` — `/metrics`
